## 2. Mathematical Foundation

### 2.1 Generative Mixture Model Formulation

A Gaussian Mixture Model models the probability density function $p(x)$ of an observed feature vector $x \in \mathbb{R}^D$ as a convex linear combination of $K$ multivariate Gaussian component densities:

$$p(x) = \sum_{k=1}^K \pi_k \, \mathcal{N}(x \mid \mu_k, \Sigma_k)$$

Where:
* $K$ is the number of mixture components (`n_components`).
* $\pi_k$ is the prior mixture weight for component $k$, satisfying:
  $$\sum_{k=1}^K \pi_k = 1, \quad \pi_k \ge 0$$
* $\mu_k \in \mathbb{R}^D$ is the mean vector of component $k$.
* $\Sigma_k \in \mathbb{R}^{D \times D}$ is the covariance matrix of component $k$.
* $\mathcal{N}(x \mid \mu_k, \Sigma_k)$ is the multivariate Gaussian density:
  $$\mathcal{N}(x \mid \mu_k, \Sigma_k) = \frac{1}{(2\pi)^{D/2} |\Sigma_k|^{1/2}} \exp\left( -\frac{1}{2} (x - \mu_k)^\top \Sigma_k^{-1} (x - \mu_k) \right)$$

### 2.2 Posterior Regime Membership Probabilities

Given an observation $x_i$, the posterior probability $\gamma_{ik}$ that observation $x_i$ was generated by component $k$ is given by Bayes' theorem:

$$\gamma_{ik} = P(z_i = k \mid x_i) = \frac{\pi_k \, \mathcal{N}(x_i \mid \mu_k, \Sigma_k)}{\sum_{j=1}^K \pi_j \, \mathcal{N}(x_i \mid \mu_j, \Sigma_j)}$$

In RegimeX, `predict_proba()` outputs this exact posterior matrix $[\gamma_{ik}]$ remapped to canonical regime order.

For every observation row $i$:
$$\sum_{k=0}^{K-1} \gamma_{ik} = 1.0 \pm 10^{-6}, \quad 0 \le \gamma_{ik} \le 1$$

### 2.3 Hard Regime Assignment

The discrete canonical regime classification returned by `predict()` is defined by maximum a posteriori (MAP) assignment:

$$\operatorname{regime}(x_i) = \underset{k}{\operatorname{argmax}} \, P(z_i = k \mid x_i)$$

This mathematical formulation guarantees that `predict(X)[i] == argmax(predict_proba(X)[i])` across all valid observations without exception.

## 3. Covariance Geometries

RegimeX supports all four standard covariance parameterizations via `covariance_type`:

| Covariance Type | Parameter Constraints | Free Parameters | Use Case & Economic Interpretation |
| :--- | :--- | :--- | :--- |
| `full` (Default) | Each component has independent general symmetric positive-definite $\Sigma_k$. | $K \cdot \frac{D(D+1)}{2}$ | General regime geometries where features exhibit distinct correlation structures per regime. |
| `tied` | All components share an identical covariance matrix $\Sigma$. | $\frac{D(D+1)}{2}$ | Regimes differ only in feature means; correlation and variance structures remain invariant across regimes. |
| `diag` | Each component has a diagonal covariance matrix $\Sigma_k = \operatorname{diag}(\sigma_{k1}^2, \dots, \sigma_{kD}^2)$. | $K \cdot D$ | Features are assumed conditionally uncorrelated within each regime; computationally efficient and robust against overfitting. |
| `spherical` | Each component has spherical isotropic variance $\Sigma_k = \sigma_k^2 I$. | $K$ | Assumes equal variance across all dimensions within each component; similar to soft probabilistic KMeans. |

## 5. Configuration & Pre-Execution Validation

GMM execution is governed by the immutable Pydantic model `GMMModelConfig`:

```python
class GMMModelConfig(BaseModel):
    model_name: str = "gmm"
    model_version: str = "1.0.0"
    n_components: int = 4            # [1..50]
    covariance_type: str = "full"    # "full" | "tied" | "diag" | "spherical"
    random_state: int = 42           # Deterministic reproducibility
    max_iter: int = 100              # [1..10000]
    tol: float = 1e-3                # EM convergence threshold > 0.0
    reg_covar: float = 1e-6          # Positive covariance diagonal regularization > 0.0
    init_params: str = "kmeans"      # "kmeans" | "k-means++" | "random" | "random_from_data"
    feature_names: tuple[str, ...] = ()
```

### Domain Validation Rules
* `n_components >= 1` (rejects 0 or negative counts).
* `covariance_type` restricted strictly to `{"full", "tied", "diag", "spherical"}`.
* `max_iter >= 1`, `tol > 0.0`, `reg_covar > 0.0`.
* `init_params` restricted strictly to `{"kmeans", "k-means++", "random", "random_from_data"}`.
* `n_samples >= n_components`: Fitting on fewer samples than components raises `InsufficientTrainingDataError`.

## 6. Deterministic Component Canonicalization & Probability Remapping

### 6.1 The Permutation Problem
In unconstrained mixture modeling, component indices ($0, \dots, K-1$) returned by expectation-maximization are arbitrary and sensitive to initialization seeds or dataset ordering. Uncontrolled raw IDs produce unstable, unreproducible regime assignments across research runs.

### 6.2 RegimeX Canonicalization Algorithm
To guarantee deterministic stability, RegimeX canonicalizes components using invariant, unscaled feature signatures:

1. **Unscale Component Means**:
   $$\mu_k^{\text{unscaled}} = \operatorname{scaler.inverse\_transform}(\mu_k^{\text{scaled}})$$
2. **Compute Invariant Feature Signature**:
   For each component $k$, construct a deterministic tuple of unscaled feature means sorted alphabetically by feature name:
   $$\operatorname{sig}(k) = \left( \mu_k^{\text{unscaled}}[f] \right)_{f \in \operatorname{sorted}(\text{feature\_names})}$$
3. **Lexicographical Sort & Mapping**:
   Sort raw components by $(\operatorname{sig}(k), k)$ to assign canonical indices:
   $$\text{raw\_id} \xrightarrow{\text{sort}} \text{canonical\_regime\_id} \in \{0, \dots, K-1\}$$
4. **Canonical Profile Labeling**:
   Assign standard neutral labels: `REGIME_0`, `REGIME_1`, ..., `REGIME_{K-1}`.

### 6.3 Column Remapping for `predict_proba()`
Because canonical IDs permute raw component indices, the posterior probability matrix must be remapped column-wise:

$$\operatorname{canonical\_probs}[:, c] = \operatorname{raw\_probs}[:, \operatorname{canonical\_to\_raw}[c]]$$

This ensures that column $c$ in `predict_proba()` always corresponds strictly to `REGIME_c`.

## 7. Numerical Stability & Regularization

Gaussian Mixture Models can suffer from covariance singularity (where a component collapses onto a single observation, causing $|\Sigma_k| \to 0$ and likelihood to explode to infinity).

RegimeX enforces numerical stability through:
1. **Covariance Regularization (`reg_covar`)**:
   Adds a positive constant $\epsilon I$ (default $\epsilon = 10^{-6}$) to the diagonal of every component covariance matrix:
   $$\Sigma_k^{\text{reg}} = \Sigma_k + \epsilon I$$
2. **Strict Validation**: `reg_covar > 0` is enforced at configuration time.
3. **Finite Domain Verification**: `FeatureMatrix` explicitly checks and rejects NaN, $+\infty$, and $-\infty$ values prior to training.
4. **Row Probability Clipping & Normalization**: Small numerical underflows are bounded and renormalized to prevent divide-by-zero or non-finite probabilities.

## 8. Anti-Leakage Preprocessing & No Lookahead Bias

RegimeX strictly enforces zero lookahead bias across all statistical and machine learning models:

1. **Strictly In-Sample Scaling**:
   ```python
   # Training phase
   scaler = StandardScaler()
   x_scaled = scaler.fit_transform(x_raw)
   gmm.fit(x_scaled)
   ```
2. **Frozen Inference Transformation**:
   ```python
   # Inference phase (predict and predict_proba)
   # NEVER refit or update scaler parameters on out-of-sample data
   x_scaled = self._scaler.transform(x_raw)
   ```
3. **Historical Prefix Invariance**:
   Predicting on a historical sub-window $[t_0, \dots, t_k]$ produces identical canonical IDs and probabilities regardless of whether subsequent future observations $[t_{k+1}, \dots, t_n]$ are appended or modified.
